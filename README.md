# Career Quest — AI-навигатор развития сотрудника

Проект команды **Raknihc** для HackAlem AI, кейс АО «Народный Банк Казахстана».
Помогаем сотруднику выбирать активности для развития, HR — видеть дефициты навыков.

## Реализовано

В ветке `feat/app-ui` работает локальный **FastAPI + SQLite backend**:

- хранение профилей, каталога навыков и мероприятий, истории и новых выполнений;
- проверяемый импорт стартовых JSON/CSV одной транзакцией, без удаления данных при повторном запуске;
- API профилей, истории, рекомендаций, симуляции и выполнения; Swagger `/docs`;
- защита от повторного выполнения и повторной отправки запроса, включая одновременные запросы;
- интерфейс подключения AI-движка: на каждый вызов передаётся свежий снимок данных SQLite;
- mock-ответы с реальными ID и названиями мероприятий; поле `mode: mock` явно отмечает заглушку.

**Сейчас mock не рассчитывает прирост навыков, прогресс или рейтинг.** Навыки в
симуляции не меняются, числовые оценки неизвестны (`null`). Выполнение сохраняется
в историю и исключает завершённую активность из следующих mock-рекомендаций.
Frontend, LLM, HR-аналитика, авторизация и HTTP-импорт пока не реализованы.

## Установка и запуск

Нужен Python 3.11+ с поддержкой `venv`; проверено на Python 3.14.
Команды выполняются из корня репозитория.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m backend.app.import_dataset /path/to/career_quest_dataset
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

На Debian/Ubuntu при ошибке `ensurepip is not available` нужно установить пакет
`python3-venv` для используемой версии Python.

Открыть **http://127.0.0.1:8000/docs**. Проверка состояния — `/health`.

В текущем рабочем окружении сервер уже запущен фоновой пользовательской службой
`career-quest-api`. Проверить её можно через `systemctl --user status career-quest-api`,
остановить — `systemctl --user stop career-quest-api`. Автозапуск после перезагрузки
компьютера не настроен; повторный запуск выполняется командой Uvicorn выше.

Без импорта сервер тоже запускается: `dataset_loaded: false`, список сотрудников
пуст, каталог возвращает понятную ошибку `dataset_not_loaded`.

В папке датасета ожидаются `employees.json`, `events.json`, `skills.json`,
`activity_history.csv`. Исходные данные и SQLite не входят в Git. Стартовый
датасет: 200 сотрудников, 60 навыков, 32 профиля требований, 40 мероприятий,
2 743 записи истории. В репозитории есть только небольшие mock-примеры ответов
в `docs/examples/` и независимый синтетический набор для тестов.

По умолчанию БД — `data/private/career-quest.sqlite3`, дата среза — **2026-10-01**.
Настройки окружения описаны в `.env.example`; файл `.env` автоматически не читается.
Для переопределения экспортируйте переменные перед запуском:

```bash
export CQ_DB_PATH=/absolute/path/to/career-quest.sqlite3
export CQ_AS_OF_DATE=2026-10-01
```

Повторный импорт тех же файлов ничего не перезаписывает. Другой датасет в уже
заполненную БД отклоняется: для него задайте новый `--db` или `CQ_DB_PATH`.
Для резервной копии работающей SQLite используйте SQLite backup API; простое
копирование одного файла во время работы не учитывает журнал WAL.

## Проверочный сценарий

1. `GET /api/v1/employees/E0001` — профиль сотрудника.
2. `GET /api/v1/employees/E0001/recommendations` — mock-карточки с реальными событиями.
3. `POST /api/v1/employees/E0001/simulations` — передать `event_id` выбранной карточки
   и её `session_date` для мероприятия по расписанию.
4. В Swagger вызвать `POST /api/v1/employees/{id}/completions`, задать
   `Idempotency-Key: demo-1`. Для `self_paced` передать только `event_id`;
   сессию по расписанию можно завершить в её расчётную дату.
5. Проверить `/history`, `/completions` и новые `/recommendations`.
   Тот же ключ и тело возвращают сохранённый результат без второй записи;
   другой ключ для уже завершённой активности возвращает 409.

Профиль хранит оценку на `last_review_date` и не перезаписывается при завершении.
Реальный движок должен восстановить текущие навыки по профилю и актуальной истории.
Это предотвращает двойное начисление прироста. Формул роста навыков в backend нет.

## Тесты

```bash
.venv/bin/python -m pytest -q
```

Тесты используют временные БД: проверяют импорт и ошибки ссылок, сохранение после
перезапуска, идемпотентность, гонку двух выполнений, отдельные сессии клуба,
откат при ошибке движка, CORS и передачу актуального контекста движку.

## Интеграция и ограничения

- [API и контракт движка](docs/api-contract.md), [mock-примеры](docs/examples/).
- [Правила датасета](docs/dataset-notes.md), [разделение задач](docs/work-plan.md).
- Настоящий движок подключается через `create_app(settings, engine=...)` и Protocol
  в `backend/app/engine_port.py`; каталог `backend/app/engine/` оставлен участнику AI.
- API пока предназначен для локальной разработки: разграничение сотрудник/HR —
  отдельная следующая задача. Backend слушает `127.0.0.1`; публично он не развёрнут.
- CORS разрешает frontend на `localhost:5173` и `127.0.0.1:5173`; CORS не заменяет авторизацию.
- Доска планирования запущена отдельно от приложения Career Quest.
- LLM и внешний API не выбраны и не подключены. Секреты и `.env` исключены из Git.
- Прогресс по навыкам не означает гарантию повышения. Публичных рейтингов сотрудников нет.
