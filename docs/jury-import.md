# Добавочный импорт профилей и истории

Только HR: `POST /api/v1/hr/imports`, Bearer-токен. Это добавление данных к
существующему каталогу, а не замена стартового датасета. Отсутствие прав — 403,
отсутствие сессии — 401. Учётные записи и роли через импорт не создаются.

## Тело и результат

```json
{
  "employees_json": "[{...полный профиль Employee...}]",
  "history_csv": "record_id,employee_id,event_id,date,due_date,status,completion_pct,score,feedback_rating,assigned_by,completed_at\n...",
  "dry_run": true
}
```

Достаточно одного файла. Это JSON-запрос со строковым содержимым файлов;
имена/пути файлов не отправляются и на сервере не открываются. `dry_run: true`
проверяет пакет и текущую БД, не сохраняет его. `false` повторяет всю проверку
в транзакции `BEGIN IMMEDIATE` и сохраняет пакет целиком. Между проверкой и
сохранением БД могла измениться — финальный результат всегда проверяется заново.

Ответ:

```json
{
  "dry_run": true,
  "employees_added": 1,
  "employees_skipped": 0,
  "history_added": 0,
  "history_skipped": 0,
  "employee_ids": ["JURY_001"]
}
```

В preview `added` означает количество будущих добавлений. В сохранении —
фактическое количество. Повтор того же пакета, включая одновременную отправку,
пропускает уже существующие идентичные записи. Вся история и новые профили сразу
доступны `EngineContext`, списку сотрудников и `/hr/overview`.

## JSON

Массив полных `Employee` или объект `{"employees": [...], "meta": {...}}`.
`meta` необязателен; `meta.as_of_date`, если указан, должен совпадать с серверным
`CQ_AS_OF_DATE`. До 500 профилей. Пример: [employees.json](../frontend/public/templates/employees.json).
Все поля схемы обязательны, кроме явно допускающих null. Навыки — целые числа 0–5.
Проверяются известные навыки, роль/грейд, цель и ссылка на руководителя, в том числе
внутри того же пакета. Дата найма ≤ дата оценки ≤ дата среза. Повтор ID внутри файла
или существующий ID с другим содержимым — ошибка; обновление профилей этим API запрещено.

## CSV

UTF-8 (BOM разрешён), разделитель — запятая. До 10 000 записей. Заголовок:

```csv
record_id,employee_id,event_id,date,due_date,status,completion_pct,score,feedback_rating,assigned_by,completed_at
```

`completed_at` можно опустить из всего файла; остальные колонки обязательны.
Пустые ячейки преобразуются в null; даты — YYYY-MM-DD. Пример структуры строки:

```csv
J_HISTORY_001,JURY_001,EV_012,2026-09-10,,completed,100,,,self,2026-09-20
```

Сотрудник должен существовать в БД или JSON этого пакета, мероприятие — в каталоге.
Дата записи не позже среза; при известном завершении `date ≤ completed_at ≤ as_of_date`.
Завершение требует `status=completed`, `completion_pct=100`. Для других статусов
`completed_at` должно быть пустым. Допустимые статусы и диапазоны — в `/openapi.json`.

Новый record_id не позволяет повторно начислить уже завершённое добровольное событие.
Для клуба `EV_036` уникальность — сотрудник + мероприятие + дата сессии. Разные даты
допускаются. Повторное обязательное обучение сохраняется как отдельные записи истории.
При отсутствующей `completed_at` адаптер использует `date` для расчёта навыков;
для self-paced это допущение, поэтому по возможности передавайте точную дату завершения.

## Ошибки

HTTP 422, без сохранения каких-либо строк:

```json
{
  "detail": {
    "code": "invalid_import",
    "message": "Импорт не сохранён. Исправьте указанные ошибки.",
    "issues": [{"file":"employees.json","row":1,"field":"skills.UNKNOWN","message":"Неизвестный ID навыка."}]
  }
}
```

Показываются первые 100 ошибок. Для JSON row — номер объекта (с 1); синтаксическая
ошибка JSON показывает физическую строку. Для CSV — номер записи с учётом заголовка
(с 2); многострочная кавычечная ячейка считается одной записью. `row: null` означает
ошибку всего файла. Ошибки формы HTTP-запроса возвращаются стандартным `detail[]` FastAPI.
Лимит каждого файла — 2 МБ; пустой CSV с одним корректным заголовком допустим.
